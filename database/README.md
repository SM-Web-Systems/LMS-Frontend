# Database setup for SM Web Systems LMS server

Use these from your **SM-Web-Systems-LMS-Server** repo when you see `SqliteError: no such table: users`.

## 1. Create tables

**Option A – from the server repo using the SQL file path:**

```bash
cd /path/to/SM-Web-Systems-LMS-Server
# If your DB file is e.g. ./data/lms.db:
sqlite3 data/lms.db < /path/to/SM-Web-systems-LMS/database/schema.sql
```

**Option B – run schema from Node in the server repo:**

In your server project, after the DB connection is set up, run the schema once at startup (e.g. in `src/config/database.ts` or a one-off script):

```ts
import Database from 'better-sqlite3';
import fs from 'fs';
import path from 'path';

const db = new Database(process.env.DATABASE_PATH || 'data/lms.db');
const schema = fs.readFileSync(path.join(__dirname, '../../database/schema.sql'), 'utf8');
db.exec(schema);
```

Adjust the path to `schema.sql` so it points to this repo’s `database/schema.sql` (or copy `schema.sql` into the server repo and path to that).

## 2. Seed admin and student users

The server must store **hashed** passwords (e.g. bcrypt). You need to insert users with hashes generated by the same library/rounds your auth uses.

**From the server repo**, run a one-off seed script. Example using bcrypt:

```bash
cd /path/to/SM-Web-Systems-LMS-Server
node -e "
const bcrypt = require('bcrypt');
const Database = require('better-sqlite3');
const db = new Database(process.env.DATABASE_PATH || 'data/lms.db');
const crypto = require('crypto');
const id = () => crypto.randomUUID();
async function seed() {
  const adminHash = await bcrypt.hash('admin123', 10);
  const studentHash = await bcrypt.hash('student123', 10);
  const now = new Date().toISOString();
  db.exec(\`
    INSERT OR IGNORE INTO users (id, name, email, password_hash, role, created_at, updated_at)
    VALUES
      ('\${id()}', 'Admin', 'admin@smwebsystems.com', '\${adminHash}', 'admin', '\${now}', '\${now}'),
      ('\${id()}', 'Demo Student', 'student@smwebsystems.com', '\${studentHash}', 'student', '\${now}', '\${now}')
  \`);
  console.log('Seeded admin@smwebsystems.com and student@smwebsystems.com');
}
seed().catch(console.error).finally(() => db.close());
"
```

Or add a `scripts/seed.ts` (or `seed.js`) in the server that uses your existing DB and bcrypt setup to insert the same two users, then run it with `npx tsx scripts/seed.ts` (or `node scripts/seed.js`).

## 3. Restart the server

After creating tables and seeding:

```bash
npm run dev
```

Then log in on the frontend with:

- **Admin:** `admin@smwebsystems.com` / `admin123`
- **Student:** `student@smwebsystems.com` / `student123`

## Column names

If your server uses different column names (e.g. `password` instead of `password_hash`), either:

- Change this schema to match the server, or  
- Change the server’s `authController` / auth layer to use `password_hash` (and the same id/name/email/role columns as in `schema.sql`).
